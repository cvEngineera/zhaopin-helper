# 智联投递助手（zhaopin-helper）

[![打包](https://github.com/cvEngineera/zhaopin-helper/actions/workflows/pack.yml/badge.svg)](https://github.com/cvEngineera/zhaopin-helper/actions/workflows/pack.yml)

一个用于**学习 Chrome 扩展开发**的示例项目：如何在一个**结构未知、随时可能改版的 SPA** 上做元素识别、状态管理与流程编排。

> 架构参考 [boss-helper](https://github.com/Ocyss/boss-helper)，用**原生 JS + Shadow DOM** 重写，不使用任何构建工具，克隆后可直接「加载已解压」运行。

## 技术上值得看什么

如果目的是学 Chrome 扩展，这几点比"能投多少简历"有价值得多：

| 技术点 | 位置 | 解决什么问题 |
|---|---|---|
| **四级页面结构识别** | `content/common.js` `scanCards()` | 面对随时改版、没有稳定 class 名的站点，如何找到目标元素。策略递进：自定义选择器 → 已知容器 → 特征链接 → 文本启发式 |
| **页面类型自动分类** | `detectPageType()` | 同一站点的列表页/分栏页/详情页三种形态，用 DOM 特征判断该走哪条路径 |
| **Shadow DOM 样式隔离** | `content/list.js` `CSS` | 插件 UI 不被宿主页面污染，也不污染宿主 |
| **跨标签页协调** | `claimSlot()` / `claimJob()` | 多页面并行时，用共享存储实现"全局限速槽"与"任务认领"，避免重复执行 |
| **配置版本迁移** | `getConfig()` + `MIGRATIONS` | 版本化配置 + 增量迁移，老用户升级不丢设置 |
| **直接读扩展存储** | `tools/read-extension-storage.cjs` | 用 `classic-level` 读 LevelDB，绕过 UI 备份/核对扩展配置 |
| **带闸门的打包脚本** | `tools/pack.mjs` | 零依赖手写 ZIP；出包前扫描手机号/邮箱/密钥，命中即拒绝打包 |
| **纯逻辑单元测试** | `test/logic.test.js` | 89 项不依赖浏览器的测试，用 DOM 桩 + 内存 storage 桩验证解析与协调逻辑 |

## 功能概览

- **职位识别**：列表页 / 分栏页 / 详情页自动识别，支持手动框选兜底
- **筛选链**：关键词、薪资（统一折算月薪 K）、公司名、规模、学历、猎头/外包、已处理去重、同公司归一化去重、同 HR 去重、公司黑名单
- **执行路径**：列表直投 / 点卡片后右侧投 / 开详情页，统一的结果判定状态机
- **节奏控制**：随机间隔、批次长停、投前/投后停留、时段窗口、失败指数退避
- **并行**：多搜索页共用全局限速槽 + 跨页岗位认领 + 一键全停
- **可观测**：投递台账（CSV 导出）、回复率统计、待跟进提醒、执行日志
- **诊断**：一键导出页面结构报告（计数 + class 采样 + 卡片 HTML），用于校准选择器

> 全部在本地浏览器内运行，不采集上传任何数据。唯一的出网请求是可选的大模型 API（地址与密钥由使用者自填，默认关闭）。

## 打包好的成品（CI 自动生成）

`dist/zhaopin-helper-<版本>.zip` 可直接安装（解压后「加载已解压的扩展程序」）。

这个 zip **由 GitHub Actions 自动生成**：每次 push 到 main 且改动涉及源码，工作流会

1. 跑 `node test/logic.test.js`（89 项，不通过就不打包）
2. 跑 `node tools/pack.mjs`（语法检查 + 敏感信息闸门，命中即拒绝出包）
3. 若 `dist/` 有变化，用 `github-actions[bot]` 身份提交回去

所以**不要手动改 `dist/`**，改了也会被下次构建覆盖。工作流文件：`.github/workflows/pack.yml`。

本地想自己打一份：

```bash
node tools/pack.mjs     # 产物同样落在 dist/
```

## 安装（仅用于本地学习）

1. 打开 `chrome://extensions`（Edge 为 `edge://extensions`）
2. 右上角开启「开发者模式」
3. 点「加载已解压的扩展程序」，选择本仓库根目录
4. 打开任意智联招聘页面，右下角出现悬浮球即为加载成功

需要 Chrome 116+（用到 `chrome.storage.session`）。

## 目录结构

```
manifest.json                      MV3 清单（权限仅限 *.zhaopin.com）
background.js                      Service Worker：开标签页、派发任务、通知、AI 代理
content/
  common.js                        配置 / 存储 / 卡片解析 / 筛选链 / 统计 / 台账 / 协调
  list.js                          悬浮球 UI + 调度引擎（复杂度主要在这）
  detail.js                        详情页执行器（点投递 → 判定结果 → 上报）
icons/                             16 / 48 / 128
test/logic.test.js                 89 项纯逻辑测试
.github/workflows/pack.yml         CI：push 时跑测试 → 打包 → 提交 dist
dist/                              构建产物（自动生成，勿手改）
tools/pack.mjs                     打包 + 敏感信息闸门
tools/read-extension-storage.cjs   读取 Chrome 扩展存储（LevelDB）
preview.html                       面板 UI 静态预览
```

## 隐私

- 数据全部存本地 `chrome.storage.local`（配置、去重记录、统计、日志、台账、可选简历附件），**无账号、无云端、无埋点**
- 全包只有一处 `fetch`：可选的大模型 API，地址与密钥由使用者填写
- 面板「配置 → 数据与隐私」可一键清空
- 打包脚本出包前会扫描手机号、邮箱、身份证、密钥，命中即拒绝出包

## 已知限制

- **只适配智联招聘**，选择器会随平台改版失效；失效时用「框选卡片」手动指定一次即可
- 同 HR 去重依赖详情页能读到招聘者姓名，读不到时退化为同公司去重
- 简历附件用 `DataTransfer` 模拟 drop 事件挂载；投递弹窗没有附件入口时静默跳过
- 不做验证码处理，遇到即停止（有意为之）
